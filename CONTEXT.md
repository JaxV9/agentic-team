## What is this project?

`agentic-team` is an **autonomous AI agent orchestrator** built with **LangGraph** (TypeScript). It simulates a software development team made up of specialized agents, each with a precise role in a sequential delivery pipeline.

The LLM used is **local Ollama** (model: `qwen2.5-coder:7b`, `temperature: 0.2`, `numCtx: 8192`).

## How It Works

### LangGraph Architecture

The [`src/index.ts`](src/index.ts) file defines:

1. **The LLM**: a shared `ChatOllama` instance used by all agents.
2. **The State**: a LangGraph `Annotation.Root` with 3 fields:
   - `input: string` — the initial user request
   - `result: string` — the last agent output
   - `logs: string[]` — cumulative log (append reducer)
3. **Agent nodes**: each agent is an `async (s: S) => {...}` function that calls the LLM with its system prompt (read from the corresponding `.md` file) and the state `input`.
4. **The StateGraph**: nodes are connected sequentially via `.addNode()` / `.addEdge()` / `.addConditionalEdges()`.

### Agent Prompt Design

Each `src/agent_systems/agent_xxx.md` file is the **system prompt** of its agent. It defines:
- The agent's role and mission
- Strict execution rules
- The expected output format (Markdown + JSON control payload)

The **JSON control payload** at the end of each agent response contains:
- `phase` / `status` — the current state
- `next_agent` — the name of the next agent (used by LangGraph for conditional routing)

## Sequential Agent Flow

```
PO Agent
  └─► ⏸️ Human Validation (WAITING_HUMAN_VALIDATION)
        └─► Git Agent (INIT) — creates the feature branch
              └─► Architect Agent — generates ARCHITECTURE.md + API_CONTRACTS.md
                    └─► Backend Dev Agent — implements the API
                          └─► Frontend Dev Agent — implements the UI
                                └─► Cyber Security Agent — security audit
                                      ├─ ❌ → routes back to Backend / Frontend / Architect
                                      └─ ✅ → QA Agent — functional tests
                                                ├─ ❌ → routes back to Backend / Frontend / Architect
                                                └─ ✅ → PO Agent (review)
                                                          ├─ ❌ iter < 3 → retry loop
                                                          ├─ ❌ iter ≥ 3 → HUMAN_ESCALATION
                                                          └─ ✅ → Git Agent (FINALIZE) — commit/tag/release
                                                                        └─► ⏸️ Final human validation
```

**Key rule**: the flow is **strictly sequential**. Backend and Frontend do **not** run in parallel.

## Important Conventions

- **Never modify agent prompts** without understanding their JSON control payload — that is what LangGraph uses for routing.
- **`next_agent`** (singular, string) is the convention across all payloads — not `next_agents` (array).
- Agents **do not write application code** in their prompts — they produce Markdown specs and reports.
- The LLM runs **locally via Ollama** — no API key required, but Ollama must be running locally.
